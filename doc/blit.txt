1. Introduction                                            *blit-introduction*

blit.nvim renders images inside Neovim using the kitty graphics protocol.
No ImageMagick. No luarocks. No external binaries. Pure Lua.

Status: early v0.x. `show()` places a PNG at a buffer position using
reserved `virt_lines` and the kitty graphics protocol; `clear()` and
`clear_all()` remove placements. A placement scrolled partway past a window
edge shows a cropped slice of the image rather than disappearing; it is
hidden only once it has no overlap with the window at all. See
`docs/spec/renderer-placement.md` in the repository for the full design.

==============================================================================
2. Requirements                                            *blit-requirements*

- Neovim >= 0.10
- One of the following terminals: kitty, WezTerm, Ghostty
- tmux is explicitly unsupported in v0.x; blit no-ops under tmux
- GUI frontends and `--embed` (e.g. Neovide) are unsupported; blit no-ops

Run `:checkhealth blit` to see detection results for your environment. On
Neovim >= 0.12 it also lists any error the terminal sent back for an image
(e.g. a PNG it rejected); on 0.10 / 0.11 those errors are not available.
WezTerm sends no such error for a rejected PNG, so none is listed there.

3. Setup                                                          *blit-setup*
>lua
    require("blit").setup({
      -- see |blit-config| for available options
    })
<
`setup()` is idempotent and safe to call more than once.

4. API                                                               *blit-api*

                                                              *blit.setup()*
setup({opts})
    Merge {opts} into blit's configuration. Does no I/O, terminal
    detection, or autocmd registration.

                                                               *blit.show()*
show({path}, {opts})
    Show the PNG at {path} anchored under buffer line {opts.lnum}.
    Returns a handle table on success, or `nil, err_msg` on failure
    (unsupported environment, missing/oversized file, not a valid PNG,
    or bad arguments).

    {opts} is a table:
      width       target placement width, in cell columns. At least one of
                  {width}/{height} is required; if omitted, derived from
                  the other and the PNG's native aspect ratio.
      height      target placement height, in cell rows. At least one of
                  {width}/{height} is required; if omitted, derived from
                  the other and the PNG's native aspect ratio.
      buf         buffer to anchor in (default: current buffer of {win})
      win         window to anchor in (default: current window)
      lnum        1-indexed anchor line (default: {win}'s cursor line)
      col         0-indexed horizontal offset of the image's left edge
                  from the window's text-area left edge, in display cells
                  (default: 0). A cell count, not a byte column: it does
                  not depend on the anchor line's text. To align with a
                  character, pass e.g.
                  `vim.fn.strdisplaywidth(line:sub(1, byte_col))`. Must be
                  a non-negative integer. An image pushed partway past
                  the window's right edge is cropped; pushed entirely
                  past it, hidden.
      z_index     kitty placement z-index (default: unset)
      cell_aspect_ratio  assumed terminal cell width-px/height-px ratio,
                  used only to derive an omitted {width}/{height} (default:
                  |blit-config.cell_aspect_ratio|)

    blit reads the PNG's native pixel dimensions to support cropping a
    partially-visible placement (e.g. a placement scrolled halfway off a
    window edge shows a cropped slice instead of hiding entirely) and, when
    the caller omits one of {width}/{height}, to derive it from the other
    under the assumed {cell_aspect_ratio}. blit never queries the terminal
    for its real cell-pixel size, so this is an approximation; when both
    {width} and {height} are supplied, they pass through unvalidated.

    Calling |blit.show()| again for the same {path} (matching file content,
    by `(path, mtime)`) reuses the already-transmitted image data instead of
    re-sending it, adding an independent placement rather than a redundant
    copy. This is also how to display the same image in more than one
    window at once — e.g. after `:split` — since one handle is bound to one
    {win}: call |blit.show()| a second time with {opts.win} set to the
    second window and the same {path}.

                                                              *blit.clear()*
clear({handle})
    Remove the placement and extmark for a handle returned by |blit.show()|.
    The transmitted pixel data is kept (cheap to re-show the same file
    later); it is only freed when Neovim exits.

                                                          *blit.clear_all()*
clear_all()
    Calls |blit.clear()| on every currently active handle.

==============================================================================
5. Configuration                                                 *blit-config*

Defaults: >lua
    {
      max_file_bytes = 5 * 1024 * 1024,
      debounce_ms = 16,
      cell_aspect_ratio = 0.5,
    }
<
                                                    *blit-config.max_file_bytes*
max_file_bytes ~
    Maximum PNG file size blit will read synchronously. Larger files are
    refused with an error return value.

                                                      *blit-config.debounce_ms*
debounce_ms ~
    Debounce interval (milliseconds) for scroll/resize-driven redraws: a
    single recompute runs this long after the last `WinScrolled`/
    `WinResized` event in a burst, never one recompute per event.

                                              *blit-config.cell_aspect_ratio*
cell_aspect_ratio ~
    Assumed terminal cell width-px/height-px ratio, used only to derive a
    |blit.show()| {opts.width}/{opts.height} the caller omitted from the
    other and the PNG's native aspect ratio. blit does not query the
    terminal for its real cell-pixel size, so this is a fixed
    approximation; override per-call with {opts.cell_aspect_ratio} if your
    font's cell metrics differ noticeably. Ignored when the caller supplies
    both {width} and {height}.
